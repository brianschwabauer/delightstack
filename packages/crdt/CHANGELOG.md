# @delightstack/crdt

## 0.3.0

### Minor Changes

- ae37430: The **client** half: `@delightstack/crdt/client` now exists alongside `/server`, and the `exports` map lists it. `CrdtClient` owns a set of open Loro documents, their local persistence and the conversation with the document servers; it owns neither the connection nor the schema.

  **The bootstrap gate, which is the reason most of this is shaped the way it is.** A Loro shallow snapshot imports only into a document whose version already covers the snapshot's shallow start — an _empty_ document being the special case that always works. A rich-text editor's very first transaction writes an empty document into the CRDT, and that single operation is enough: after it, a compacted server can never bootstrap the device. `import()` returns `{ success: {}, pending: {} }`, throws nothing, and leaves the document untouched, so both sides believe they are fine while the device stops syncing forever. `open()` therefore returns a handle that is `loading`, cleared on the first of the server's `sync`, local storage already holding operations, or `bootstrap_timeout_ms` (default 1.5s, so a genuinely offline first run still works) — and `transact()` **throws `bootstrap_pending`** until then. The rule was already written down and it was not enough; the gate has teeth. `await handle.ready()` before mounting an editor.

  **Transport is injected, mirroring how the server kept it out via `syncFor()`.** `CrdtTransport` is `connected` / `send` / `onMessage` / `onConnectionChange`, and messages are structured objects carrying `Uint8Array` payloads rather than frames, so framing stays a wire decision. The message set maps one-to-one onto the server: `subscribe` → `syncFor()`, `update` → `applyUpdate()`. In a real app one connection already carries metadata sync and presence, so a CRDT package that opened its own would be a second socket, a second reconnect policy and a second auth handshake — and an interface is a transport a test can partition mid-edit. Re-subscribing on reconnect _is_ the catch-up protocol (the server answers with a version-vector diff, which covers an offline session of any length), so a transport that reconnects without firing `onConnectionChange` leaves documents stuck.

  **Durability.** `transact()` is synchronous and appends the update blob to the local pending log before returning; persistence completing and the network send are fire-and-forget. That is only enforceable with `createSyncAccessHandle()`, which is worker-only — run this layer in a SharedWorker. `OpfsCrdtStorage` still works on the main thread through `createWritable()`, where the write is merely _queued_ synchronously, and reports which you got as `.durable`. On disk each document is a snapshot plus an append-only log of framed records (updates and ack tombstones), folded every `snapshot_every` records; a truncated tail from a crash mid-append is dropped rather than failing the open. Remote blobs are logged too, since the snapshot is only rewritten periodically. Unacked local blobs are re-appended _after_ a fold even though the snapshot already contains their operations — the snapshot preserves the content but only a log record preserves the `op_id`, and without it a reload loses the ability to resend.

  **Sending.** Debounced by `send_debounce_ms` (default 200ms), with a run of never-sent commits coalesced into one update by re-exporting from the first one's version vector; the spike measured ~90 bytes of CRDT inside a ~175 byte frame per keystroke, so roughly half the traffic was framing. Blobs already on the wire are never re-coalesced — that would re-mint their `op_id` and defeat the server's deduplication — so a reconnect resends them unchanged, in order. Nothing is sent before the connection's `subscribe` has been answered, because the answer is where `reset` lives.

  **Eviction and quota are two different things.** A document stays resident `idle_evict_ms` (default 5 minutes) after its last reader, then is snapshotted and dropped from memory; `open()` restores it. A document holding unacked commits is not evicted, since dropping it leaves nothing in memory to resend from. Separately, `quota_bytes` (default 2GB) is a soft cap on local body storage swept LRU by whole document — never a resident document, and **never one holding unacked local commits**, so quota pressure can never be a route to losing an edit the server has not seen.

  **`reset` is surfaced, never applied.** When the server says this device predates the retained history, the client marks the handle unusable (`transact()` throws `reset_required`), sets `sync_state` to `error`, and calls `on_reset({ node_id, unacked_ops })`. Discarding a user's offline work is a decision a UI makes; `purge(node_id)` then `open(node_id)` is the recovery path.

  `sync_state` (`synced` / `syncing` / `offline` / `error`) and `pending_count` are Svelte 5 runes, so `svelte` is now an **optional** peer dependency. `storage: 'idb'` throws `not_implemented` on purpose: IndexedDB cannot offer the synchronous append `transact()` promises, so an IndexedDB backend would quietly weaken the contract rather than widen support. `MemoryCrdtStorage` is exported for tests and for environments with no durable storage at all.

  **Tests.** The client suite drives `CrdtClient` against the real `CrdtDocumentServer` over real SQLite through a loopback transport, including a test that first _demonstrates_ the empty-doc-then-compacted-server trap against the real server and then shows the gate preventing it. OPFS does not exist in Node and no DOM shim implements it, so storage is exercised through `MemoryCrdtStorage` — the same interface storing the same framed bytes, which keeps framing, tombstones, reload replay, snapshot folding and the quota sweep real. Not covered, deliberately: that `createSyncAccessHandle().write()` really is synchronous in a browser, the main-thread positional-append path, two-worker handle contention, and browser-initiated eviction.

## 0.2.0

### Minor Changes

- 0256a8c: New package: collaborative document storage for Cloudflare Durable Objects, built on Loro. This changeset covers the **server** half; the client and ProseMirror entries are declared but not yet implemented.

  **`CrdtDocumentServer`.** One Durable Object per document, holding one Loro document plus the append-only log that produced it, and everything derived from that pair. `applyUpdate(op_id, actor, blob)` dedupes on a client-generated `op_id` — every mutation in a local-first system crosses at least one retry boundary, so a repeat is normal traffic: it returns `applied: false` with the current frontier and the original `seq`, and appends nothing, so the _log_ does not grow on retries even though Loro's `import` is idempotent anyway. `listUpdates()` and `listSessions()` are derived from stored metadata (`frontier` after applying, `byte_size`) and never decode an update blob, which is what makes opening the history rail on every document affordable; sessions — same actor, gap under `session_gap_ms`, no checkpoint between — are computed at read time and never stored, so the grouping gap stays a UI tuning knob rather than a migration. `checkpoint()`, `restore()`, `getVersion()`, `snapshot()`, `compact()` and `runProjection()` complete the surface.

  **Entry points are pinned per environment, deliberately.** Loro ships several wasm builds behind one specifier and export-condition resolution picks a broken one in two of the three environments that matter: in workerd the `browser` build throws at module scope (the Worker never boots), and under Vite the `bundler` build is refused outright. `@delightstack/crdt/server` names `loro-crdt/bundler` and `@delightstack/crdt/client` names `loro-crdt/web` (streaming compile — the `browser` build fetches 3.2MB with a **synchronous XHR** and decodes it byte by byte on the main thread), while the root entry is types only and pulls in no wasm at all. Server code imports Loro from `src/loro.server.ts` and never from the bare specifier, so there is exactly one place to get this wrong.

  **Three methods are async, against the original design sketch.** Snapshots above `inline_snapshot_max_bytes` (512KB default) are tiered to R2, and R2 is async, so `getVersion`, `snapshot` and `compact` return promises; a synchronous `getVersion` could only ever read inline snapshots and would silently cap the document size at which history works. Everything on the hot path stays synchronous, because DO SQLite and Loro both are.

  **Compaction, and the three Loro behaviours it is built around.** `export({ mode: 'shallow-snapshot', frontiers: F })` does **not** export the state at `F` — `F` is where retained history _starts_, and the exported state is always the document's current state, so a snapshot "at a checkpoint" has to come from a throwaway document replayed to that checkpoint first. `forkAt()` is not implemented on shallow documents, so time travel is replay-then-export rather than fork; and because exporting a `checkout()`-ed document exports its whole oplog state rather than the checked-out state, the throwaway document's log must _end_ at the target. A version whose blobs were discarded and which is not a checkpoint throws `frontier_unreachable` (410) rather than being approximated with the nearest snapshot. Every checkpoint at or before the boundary gets a pinned snapshot at its exact frontier before a single blob is deleted, and steps 2–4 run in one `transactionSync`.

  **Compaction can decline, and that is the invariant rather than a failure.** Checkpoint snapshots are mandatory and cost more than the op blobs they replace on small or checkpoint-dense documents — a 9-op document was measured growing 871B → 1188B, and the package's own 10,000-edit/50-checkpoint test is another case where the snapshots outweigh the whole log. So the transaction measures its own result and rolls itself back with `skipped_reason: 'would_not_shrink'` rather than letting "compaction never increases stored bytes" be false. `below_threshold`, `retention_forever`, `nothing_to_do` and `peer_floor` are the other reasons; `{ force: true }` overrides all of them for an explicit user action.

  **The peer floor.** Once history is trimmed to a shallow start, a peer whose version predates that start is unrecoverable in _both_ directions: it cannot be caught up (a shallow snapshot imported into a document behind its shallow start returns success and changes nothing) and its own operations can never be accepted, because their dependencies are gone on the server too. Nothing throws — the device just stops syncing forever while both sides believe they are fine. So `compact()` never trims past `min(acked_seq)` over peers seen within `peer_floor_ttl_ms` (30 days). Peers are registered by `syncFor()`, which also makes the incremental-vs-bootstrap decision that cannot be delegated (`shallowSinceVV().compare(peer_version)` — an `export({ mode: 'update', from })` on a shallow document returns a blob whose dependencies were trimmed and the receiver reports success anyway), or explicitly via `notePeer()`/`forgetPeer()`. A device that reappears past the TTL is told `kind: 'reset'`, which is data-losing and must be surfaced, not performed quietly. A document with no registered peers has no floor — correct for a server-authoritative deployment, wrong for one with real offline devices.

  **Tests.** A seeded convergence harness — 2–5 peers from a common base, randomized edit scripts (insert, delete, replace, split, join, move, format, image, same-offset typing), random partition and reconnect, delivery in random order with duplicates, then every peer asserted byte-identical on content, markdown projection, block ids and version vector. 50 scenarios in CI, `CRDT_SCENARIOS=500` for nightly; failing seeds are checked in as regression cases. Plus the known-hard cases and one test per history invariant, including the real version of "every checkpoint stays checkoutable forever": 10,000 edits, 50 checkpoints, compaction run to completion, all 50 checked out and compared byte for byte. The Durable Object harness runs the real class against real SQLite through `node:sqlite`, because a mock that records SQL strings can only prove the statements were issued, not that they were right.
